Feature: Provider-agnostic authentication with switchable multi-provider support

Goal
- Keep current local Credentials auth.
- Allow enabling LDAP in parallel now or later.
- Allow adding future providers (OIDC/SAML, OAuth) without schema changes.
- Prevent duplicate user records by linking identities.

Database (idempotent)
-- Users table gets provider linkage columns if not present
DO $$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_name='users' AND column_name='auth_provider') THEN
    ALTER TABLE users ADD COLUMN auth_provider text NOT NULL DEFAULT 'local';
  END IF;
  IF NOT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_name='users' AND column_name='external_id') THEN
    ALTER TABLE users ADD COLUMN external_id text; -- provider-specific id (e.g., LDAP DN, OIDC sub)
    CREATE INDEX IF NOT EXISTS idx_users_external_id ON users(external_id);
  END IF;
  IF NOT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_name='users' AND column_name='username') THEN
    ALTER TABLE users ADD COLUMN username text;
    CREATE UNIQUE INDEX IF NOT EXISTS users_username_unique ON users(lower(username));
  END IF;
  IF NOT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_name='users' AND column_name='email_verified') THEN
    ALTER TABLE users ADD COLUMN email_verified boolean NOT NULL DEFAULT false;
  END IF;
  IF NOT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_name='users' AND column_name='last_login_at') THEN
    ALTER TABLE users ADD COLUMN last_login_at timestamp;
  END IF;
  -- Optional app status if missing
  IF NOT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_name='users' AND column_name='status') THEN
    CREATE TYPE user_status AS ENUM ('active','invited','disabled');
    ALTER TABLE users ADD COLUMN status user_status NOT NULL DEFAULT 'active';
  END IF;
END$$;

-- Optional: account linking table for future multi-link per user
CREATE TABLE IF NOT EXISTS user_identities (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  provider text NOT NULL,          -- 'local','ldap','oidc','google','azuread', etc.
  external_id text NOT NULL,       -- provider unique id (DN, sub, subject)
  email text,                      -- email seen at the provider
  username text,                   -- username seen at the provider
  created_at timestamp NOT NULL DEFAULT now(),
  UNIQUE (provider, external_id)
);
CREATE INDEX IF NOT EXISTS idx_user_identities_user ON user_identities(user_id);

Server: NextAuth multi-provider setup
- Register providers conditionally from env flags.
- Local Credentials stays as is when AUTH_ENABLE_LOCAL=true.
- LDAP provider uses read-only bind to search and user bind to verify, then upserts local user.
- OIDC/OAuth providers can be added later; on callback, upsert and link identity.

Common sign-in flow (all providers)
1) Normalize username and email to lower case.
2) Try to find existing user:
   a) by user_identities(provider, external_id)
   b) else by users.username (if provided and unique)
   c) else by users.email where email_verified=true (use caution on email-only linking)
3) If found, update first_name, last_name, email from provider if present, set last_login_at=now(), ensure users.status != 'disabled' or reject.
4) If not found, create users row with:
   auth_provider = provider
   external_id   = provider id (also store in user_identities)
   username, first_name, last_name, email
   status='active' (or 'invited' if you want an approval step)
   last_login_at=now()
5) Insert or update user_identities linking to this user.
6) Return local user id in session. Never store provider passwords.

RBAC
- Roles, department, division remain managed in app tables (Settings → Users).
- Do not sync roles from providers.

Security
- Require LDAPS or StartTLS for LDAP.
- For OIDC, validate issuer and audience, and use PKCE.
- Rate limit sign-in attempts.
- Deny login if users.status='disabled' even if provider allows.
- Audit login attempts and provider link events.

Frontend
- Login page shows available providers based on a small `/api/auth/providers` config.
- Settings → Users shows a “Linked identities” section on user detail:
  • Provider badges and external_id short hash
  • Ability for System Admin to unlink a secondary identity (not primary).
- Settings → Auth Providers page (read-only) shows which providers are enabled from env.

Account linking rules
- Primary key for link is user_identities(provider, external_id).
- Email-based linking is allowed only if email_verified=true from provider and not used by another user.
- Prevent accidental merges by requiring admin action when a conflict is detected.

Acceptance
- With only AUTH_ENABLE_LOCAL=true, local login works as today.
- Turning AUTH_ENABLE_LDAP=true adds an LDAP option on the login screen; both work.
- First LDAP login creates or links a local user and sets last_login_at.
- Disabling a user in app prevents login via any provider.
- Future: enabling OIDC provider requires no DB change; identities are recorded in user_identities and linked to the same users row.

Nice to have (later)

- Email verification for local provider to set email_verified=true.
