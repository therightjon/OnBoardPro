Change request: Auto-activate template when the first stage is added

Context
- Templates are independent snapshots once applied to candidates.
- We want a template to become Active as soon as it gets its first stage.
- Previous rule (“each stage must have ≥1 task before activation”) must be relaxed.

Goals
- When POST /api/templates/:id/stages adds (or re-activates) the FIRST active stage for a template, set templates.is_active = TRUE.
- Keep soft delete for template stages (is_active flag).
- Make DB constraints match: “ready” = at least one active stage.

DB (Postgres, idempotent)

-- 1) Relax readiness to: at least one active stage
CREATE OR REPLACE FUNCTION template_is_ready(p_template_id uuid)
RETURNS boolean LANGUAGE plpgsql AS $$
DECLARE
  stage_cnt int;
BEGIN
  SELECT COUNT(*) INTO stage_cnt
  FROM template_stages
  WHERE template_id = p_template_id AND is_active = true;

  RETURN stage_cnt > 0; -- relaxed rule
END$$;

-- 2) Trigger that enforces readiness only when turning active
CREATE OR REPLACE FUNCTION enforce_template_ready()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  IF NEW.is_active = true AND NOT template_is_ready(NEW.id) THEN
    RAISE EXCEPTION 'Template % cannot be activated until it has at least one stage', NEW.id
      USING ERRCODE = 'check_violation';
  END IF;
  RETURN NEW;
END$$;

DROP TRIGGER IF EXISTS trg_templates_guard_active ON templates;
CREATE CONSTRAINT TRIGGER trg_templates_guard_active
AFTER INSERT OR UPDATE OF is_active ON templates
DEFERRABLE INITIALLY DEFERRED
FOR EACH ROW EXECUTE FUNCTION enforce_template_ready();

API

-- 3) Stage add = UPSERT, then auto-activate if it’s the first active stage
-- Route: POST /api/templates/:id/stages
-- Body: { stage_id, order_index? }

-- SQL used by handler:
-- (a) Upsert the stage
INSERT INTO template_stages (template_id, stage_id, order_index, is_active, created_at, updated_at)
VALUES ($1, $2, COALESCE($3, 0), TRUE, now(), now())
ON CONFLICT (template_id, stage_id)
DO UPDATE SET
  is_active   = TRUE,
  order_index = COALESCE(EXCLUDED.order_index, template_stages.order_index),
  updated_at  = now();

-- (b) If this template now has exactly 1 active stage, auto-activate template
WITH s AS (
  SELECT COUNT(*) AS cnt
  FROM template_stages
  WHERE template_id = $1 AND is_active = TRUE
)
UPDATE templates t
SET is_active = TRUE, updated_at = now()
FROM s
WHERE t.id = $1
  AND s.cnt = 1        -- first active stage just (re)added
  AND t.is_active = FALSE;

Frontend

- No UI change required. After adding the first stage, refetch ['templates'] and ['templateStages', templateId] so the Status pill flips to Active.
- Keep “Add Task” behavior as-is. (Tasks can be added any time after the stage exists.)

Acceptance

- Adding the first stage to an inactive template flips Status → Active automatically.
- Adding more stages leaves Status unchanged (stays Active).
- Removing all stages (soft deactivate each) and then adding one again re-activates the template.
- Attempting to set is_active = TRUE directly still requires ≥1 active stage (DB trigger).
