Bugfix: Friendly toast for "Complete" status when required tasks are incomplete

Problem
- Changing candidate status to "completed" returns a 400 with JSON and surfaces a raw error blob in the UI.
- Expected: a clean toast that explains the issue and lists remaining required tasks with quick actions.

Backend (keep current behavior)
- Keep 400 response with body:
  { "code":"INCOMPLETE_REQUIRED_TASKS",
    "message":"Cannot mark candidate as completed. Incomplete required tasks.",
    "remaining":[
      { "id":"<uuid>", "title":"...", "stageName":"..." }
    ] }

Frontend

1) Status change mutation handler
- File: candidate detail status control component.
- Wrap PATCH /api/candidates/:id/status in try/catch.
- On non-OK, parse JSON and branch by error code.

Example:

const qc = useQueryClient();

const mutateStatus = useMutation({
  mutationFn: async (nextStatus: CandidateStatus) => {
    const r = await fetch(`/api/candidates/${id}/status`, {
      method: 'PATCH',
      headers: { 'Content-Type':'application/json' },
      body: JSON.stringify({ status: nextStatus }),
    });
    if (!r.ok) {
      const err = await r.json().catch(() => ({}));
      throw err;
    }
    return r.json();
  },
  onSuccess: (data, nextStatus) => {
    toast.success(`Status updated to ${nextStatus}`);
    qc.invalidateQueries({ queryKey: ['candidate', id] });
    qc.invalidateQueries({ queryKey: ['candidates'] });
    qc.invalidateQueries({ queryKey: ['candidateTasks', id] });
  },
  onError: (err: any, nextStatus) => {
    if (err?.code === 'INCOMPLETE_REQUIRED_TASKS') {
      // Build readable list
      const items = (err.remaining ?? []).slice(0, 5).map(
        (t: any) => `• ${t.title} (${t.stageName})`
      ).join('\n');
      toast.error(
        `Cannot mark as Completed. Finish required tasks first.\n${items}${(err.remaining?.length ?? 0) > 5 ? '\n…' : ''}`,
        { duration: 8000 }
      );
      // Optional: open Tasks tab and apply filter for required + not done
      // router.replace(`?tab=tasks&filter=required_open`);
      return;
    }
    toast.error(err?.message ?? 'Could not update status');
  }
});

2) Confirm UI when selecting "Completed"
- Keep the confirmation dialog, but remove raw error rendering.
- On confirm, call mutateStatus('completed') only once. The handler above will show the toast if blocked.

3) Optional quick action button in toast
- Add a CTA to jump to Tasks tab filtered to required+open.

import { toast } from 'sonner';
toast.custom((id) => (
  <div className="space-y-2">
    <p className="font-medium">Cannot mark as Completed</p>
    <p className="text-sm text-muted-foreground">Finish required tasks first.</p>
    <div className="mt-2">
      <Button size="sm" onClick={() => {
        // open tasks tab with filter
        // router.replace(`?tab=tasks&filter=required_open`);
        toast.dismiss(id);
      }}>View required tasks</Button>
    </div>
  </div>
));

4) Prevent raw JSON alerts globally
- In the app-level fetch wrapper, never surface Response.text() by default.
- Always attempt JSON parse and map known error codes to friendly messages.
