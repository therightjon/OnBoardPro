Feature: Inline update of Candidate Task status on Candidate Details

Goal
- On /candidates/[id], users can click a task’s current Status and change it in-place.
- Support statuses: todo, in_progress, blocked, done, canceled.
- Update persists via API, with optimistic UI and rollback on error.

RBAC
- Allow change if user has permission to edit this candidate’s tasks:
  roles ∈ {system_admin, hr_staff, department_admin, division_leader, manager}
  and within department/division scope. 
- Candidate may update only their own assigned tasks.
- Otherwise return 403.

Backend

1) PATCH /api/tasks/:taskId
   Body: { status: 'todo' | 'in_progress' | 'blocked' | 'done' | 'canceled' }
   Behavior:
   - Validate task exists and not archived.
   - Check RBAC for current user.
   - Update candidate_tasks.status and updated_at = now().
   - If setting to 'done', set completed_at = now() if NULL. If changing away from 'done', set completed_at = NULL.
   - Return updated row (id, status, completed_at, updated_at).

   Pseudo code (Drizzle/SQL):
   - SELECT candidate_id, assignee_id, status FROM candidate_tasks WHERE id = :taskId;
   - if not allowed -> 403
   - UPDATE candidate_tasks SET 
       status = :status,
       completed_at = CASE WHEN :status = 'done' THEN COALESCE(completed_at, now()) ELSE NULL END,
       updated_at = now()
     WHERE id = :taskId
     RETURNING id, status, completed_at, updated_at;

Frontend (Candidate Details page)

1) Enum map and labels
   // src/lib/task-status.ts
   export const TASK_STATUS = ['todo','in_progress','blocked','done','canceled'] as const;
   export const TASK_STATUS_LABEL: Record<string,string> = {
     todo: 'To do',
     in_progress: 'In progress',
     blocked: 'Blocked',
     done: 'Done',
     canceled: 'Canceled',
   };

2) Status cell component
   Replace the Status cell in the “Tasks by Stage” table with a clickable control:

   // src/components/task-status-cell.tsx
   'use client';
   import { useMutation, useQueryClient } from '@tanstack/react-query';
   import { TASK_STATUS, TASK_STATUS_LABEL } from '@/lib/task-status';
   import { Select, SelectContent, SelectItem, SelectTrigger, SelectValue } from '@/components/ui/select';
   import { cn } from '@/lib/utils';
   import { toast } from 'sonner';

   export function TaskStatusCell({
     taskId,
     candidateId,
     value,
     disabled,
   }: {
     taskId: string;
     candidateId: string;
     value: string;   // current status
     disabled?: boolean;
   }) {
     const qc = useQueryClient();

     const mutation = useMutation({
       mutationFn: async (nextStatus: string) => {
         const res = await fetch(`/api/tasks/${taskId}`, {
           method: 'PATCH',
           headers: { 'Content-Type': 'application/json' },
           body: JSON.stringify({ status: nextStatus }),
         });
         if (!res.ok) {
           const e = await res.json().catch(() => ({}));
           throw new Error(e?.error || 'Failed to update status');
         }
         return res.json();
       },
       onMutate: async (nextStatus) => {
         // optimistic update: snapshot
         const key = ['candidateTasks', candidateId];
         await qc.cancelQueries({ queryKey: key });
         const previous = qc.getQueryData<any>(key);
         qc.setQueryData<any>(key, (old: any) => {
           if (!old?.tasks) return old;
           return {
             ...old,
             tasks: old.tasks.map((t: any) =>
               t.id === taskId ? { ...t, status: nextStatus, completed_at: nextStatus === 'done' ? t.completed_at ?? new Date().toISOString() : null } : t
             ),
           };
         });
         return { previous, key };
       },
       onError: (err, _vars, ctx) => {
         if (ctx?.previous) qc.setQueryData(ctx.key, ctx.previous);
         toast.error((err as Error).message);
       },
       onSuccess: () => {
         qc.invalidateQueries({ queryKey: ['candidateTasks', candidateId] });
         toast.success('Status updated');
       },
     });

     return (
       <Select
         value={value}
         onValueChange={(v) => mutation.mutate(v)}
         disabled={disabled || mutation.isPending}
       >
         <SelectTrigger className={cn('w-[14rem]', mutation.isPending && 'opacity-70')}>
           <SelectValue placeholder="Set status" />
         </SelectTrigger>
         <SelectContent>
           {TASK_STATUS.map((s) => (
             <SelectItem key={s} value={s}>
               {TASK_STATUS_LABEL[s]}
             </SelectItem>
           ))}
         </SelectContent>
       </Select>
     );
   }

3) Use the cell in your Tasks table
   In the “Tasks by Stage” tab, where you render each task row:

   // within row render
   <TaskStatusCell
     taskId={task.id}
     candidateId={candidate.id}
     value={task.status}
     disabled={!task.canEditStatus}  // optional; compute from RBAC or from API
   />

4) Visual affordances
   - Keep SelectTrigger full width in the Status column if your table allows.
   - Optionally color the current status chip:
     - todo: neutral
     - in_progress: blue
     - blocked: red
     - done: green
     - canceled: gray

5) Validation and constraints
   - If a task is archived, disable the control.
   - If a task is required and status changes to canceled, optionally show a confirm dialog.

6) Accessibility
   - SelectTrigger must have aria-label="Task status".
   - Keyboard users should open the Select with Enter or ArrowDown and pick a new status.

7) Acceptance
   - Clicking the Status opens a dropdown with the 5 statuses.
   - Choosing a new status updates UI immediately and persists to the server.
   - If server rejects, UI rolls back and shows an error toast.
   - Setting status to Done stamps completed_at; setting away from Done clears completed_at.
   - Users without permission see the control disabled or do not see it at all.
