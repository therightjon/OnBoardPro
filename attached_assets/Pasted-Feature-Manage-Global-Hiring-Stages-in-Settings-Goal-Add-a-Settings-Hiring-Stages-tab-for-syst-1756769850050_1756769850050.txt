Feature: Manage Global Hiring Stages in Settings

Goal
- Add a Settings → Hiring Stages tab for system_admin and hr_staff roles.
- This page manages the global pool of hiring_stages, which are then selectable in templates and candidate tasks.

Database
-- Ensure hiring_stages table exists (idempotent)
CREATE TABLE IF NOT EXISTS hiring_stages (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL UNIQUE,
  description text,
  order_index int NOT NULL DEFAULT 0,
  is_active boolean NOT NULL DEFAULT true,
  created_at timestamp NOT NULL DEFAULT now(),
  updated_at timestamp NOT NULL DEFAULT now(),
  created_by uuid REFERENCES users(id),
  updated_by uuid REFERENCES users(id)
);

-- Add index for sorting
CREATE INDEX IF NOT EXISTS idx_hiring_stages_order ON hiring_stages(order_index);

-- Add updated_at trigger
DROP TRIGGER IF EXISTS trg_hiring_stages_updated_at ON hiring_stages;
CREATE TRIGGER trg_hiring_stages_updated_at
  BEFORE UPDATE ON hiring_stages
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

API
1) GET /api/hiring-stages
   - Returns all hiring stages ordered by order_index.
   - Include is_active flag for filtering.

2) POST /api/hiring-stages
   - Body: { name, description?, order_index? }
   - Creates new stage, auto-assign order_index if not provided.

3) PATCH /api/hiring-stages/:id
   - Update name, description, order_index, is_active.

4) DELETE /api/hiring-stages/:id
   - Soft delete → set is_active=false.

Frontend (Settings → Hiring Stages)
- Route: /settings/hiring-stages
- Add new tab item “Hiring Stages” under Settings.
- Layout:
  - Page header: “Hiring Stages”
  - Button: “+ Add Stage” (opens dialog with name, description, order_index).
  - Table/List with columns: Name, Description, Order, Status, Actions.
  - Actions: Edit (inline or dialog), Archive/Restore (toggle is_active), Delete (soft delete).

- Drag & drop ordering (optional but preferred).
  - Update order_index on drop and persist via PATCH.

- Use shadcn/ui components:
  - Data table or list view.
  - Dialog for add/edit forms.
  - Switch or Badge for active/inactive.

Access Control
- Only system_admin and hr_staff see this page.
- Others: hide the tab and return 403 on API.

Acceptance
- System admins and HR staff can create, edit, reorder, archive, and restore hiring stages.
- Templates and candidate tasks pull stages from this table.
- Soft-deleted stages cannot be assigned in new templates but remain in historical candidates.
