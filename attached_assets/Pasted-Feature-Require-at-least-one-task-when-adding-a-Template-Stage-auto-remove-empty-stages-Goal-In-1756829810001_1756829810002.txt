Feature: Require at least one task when adding a Template Stage; auto-remove empty stages

Goal
- In the “Add Stage to Template” flow, the user must pick a Stage AND at least one Task Definition before saving.
- Persist both in ONE transaction: create the template_stages row and the first template_task(s) together.
- If all tasks for a stage are removed later, prompt the user to confirm removal; on confirm, delete the stage.
- Prevent dangling stages at the DB level (cleanup trigger as an extra guard).

DB (Postgres 16, idempotent)

-- 1) Ensure template_tasks references (template_id, stage_id)
-- (Adjust names to your schema if different)
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1
    FROM information_schema.table_constraints
    WHERE table_name='template_tasks' AND constraint_name='template_tasks_template_stage_fk'
  ) THEN
    ALTER TABLE template_tasks
    ADD CONSTRAINT template_tasks_template_stage_fk
    FOREIGN KEY (template_id, stage_id)
    REFERENCES template_stages(template_id, stage_id)
    ON DELETE CASCADE;  -- removing a stage removes its tasks
  END IF;
END$$;

-- 2) Auto-remove empty stages safety net (trigger)
CREATE OR REPLACE FUNCTION remove_empty_template_stage()
RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE
  remaining int;
BEGIN
  -- When a template_task is deleted, check whether any tasks remain for its (template_id, stage_id).
  SELECT COUNT(*) INTO remaining
  FROM template_tasks
  WHERE template_id = OLD.template_id AND stage_id = OLD.stage_id;

  IF remaining = 0 THEN
    DELETE FROM template_stages
    WHERE template_id = OLD.template_id AND stage_id = OLD.stage_id;
  END IF;

  RETURN NULL;
END$$;

DROP TRIGGER IF EXISTS trg_template_tasks_remove_empty_stage ON template_tasks;
CREATE TRIGGER trg_template_tasks_remove_empty_stage
AFTER DELETE ON template_tasks
FOR EACH ROW EXECUTE FUNCTION remove_empty_template_stage();

Frontend

Dialog: “Add Stage to Template” (shown in screenshot)
- After user selects a Stage, reveal another Select for “Select Task to Add”.
- Allow selecting multiple task definitions (preferred) or at least one; disable “Add Stage” until task selection has length ≥ 1.

UI spec:
- Stage Select: required; options sourced from /api/hiring-stages?active=1 but FILTER OUT stages already on this template.
- Task Select: required (multi-select); options from /api/task-definitions?active=1, with search.
- Due rule defaults: show a compact inline group (Due Rule Type dropdown + Days/Date input) applied to all selected tasks for initial creation. Users can edit each later from the list.
- Primary button text: “Add Stage” (disabled until both Stage and ≥1 Task selected)

React behavior (TanStack Query + shadcn):
- On submit:
  • POST /api/templates/:id/stages/create-with-task
  • Optimistically add stage row (at the end) and its tasks to local caches
  • Invalidate:
     - ['templateStages', templateId]
     - ['templateTasks', templateId]
     - ['template', templateId] (to refresh Last Modified and status)

Delete last task in a stage:
- When user clicks delete on a template_task, before sending DELETE:
  • If this is the last task in that stage (compute client-side group count), show AlertDialog:
    “This is the last task in ‘{StageName}’. Removing it will also remove the stage from this template. Continue?”
  • On confirm, proceed with DELETE /api/template-tasks/:id.
  • On success:
      - If response.removedStage is set, remove stage from UI list.
      - Invalidate ['templateStages', templateId] and ['templateTasks', templateId].
  • On cancel, do nothing.

Edge cases / validation
- Prevent duplicate stage add: Stage Select should exclude already-added stages; server also guards with ON CONFLICT do nothing/update.
- Due rule UX:
  • If due_rule_type='on_start_date', hide the “days/date” input and send due_rule_value=null.
  • If 'days_*', require an integer; if 'fixed_date', require a date string.
- Access control: only system_admin and hr_staff can add/remove stages or tasks.

Acceptance
- User cannot click “Add Stage” until at least one Task is chosen.
- Adding Stage + Task(s) in one submit creates both rows; the stage instantly appears with its tasks.
- Deleting the last task in a stage prompts for confirmation; on confirm, the stage disappears (and is removed in DB).
- There are no “empty” stages in DB or UI.
