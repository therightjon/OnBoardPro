Change request: Role-aware navigation and task placement

Goal
- Show a role-based sidebar. Only system_admin and hr_staff can see Task Library and Templates.
- Candidate Tasks appear only on Candidate Profile pages. Keep a personal My Tasks view for all users.

Routes
- /dashboard → Dashboard
- /candidates → Candidates list
- /candidates/[id] → Candidate profile with Tasks section (full CRUD, scoped to this candidate)
- /tasks → Task Library (Task Definitions CRUD)
- /tasks/mine → My Tasks (assigned to current user)
- /templates → Templates list and template editing
- /analytics → Analytics
- /settings → Settings

Sidebar visibility by role
- system_admin: Dashboard, Candidates, Task Library, My Tasks, Templates, Analytics, Settings
- hr_staff: Dashboard, Candidates, Task Library, My Tasks, Templates, Analytics, Settings
- department_admin: Dashboard, Candidates, My Tasks, Analytics
- division_leader: Dashboard, Candidates, My Tasks
- manager: Dashboard, Candidates, My Tasks
- candidate: Dashboard, My Tasks

Active states
- Exact highlight rules:
  - /tasks → Task Library
  - /tasks/mine → My Tasks
  - /templates → Templates
  - /candidates and /candidates/[id] → Candidates
  - Others map one-to-one

Task placement rules
- Remove any global “All Candidate Tasks” page. Do not list all candidate tasks system-wide.
- Candidate Tasks are visible and editable only inside /candidates/[id] in a Tasks section grouped by stage.
- My Tasks shows only tasks where assignee_id = current_user and links each row to its candidate profile.
- /tasks is strictly the reusable Task Definitions CRUD. No candidate tasks should appear on this page.

Access control
- Server must enforce the same rules:
  - Block access to /tasks (Task Library) and /templates for users not in {system_admin, hr_staff}.
  - Endpoints returning task definitions or templates check the role and return 403 when unauthorized.
  - Endpoints for candidate tasks require candidate_id and verify the user has scope to that candidate.

Implementation notes
- Add a getCurrentUser() call on layout render and compute an allowedNav array per role to render sidebar items.
- Use exact path checks for active states. Do not let /tasks/mine activate Task Library.
- My Tasks query: SELECT candidate_tasks WHERE assignee_id = current_user AND archived = false ORDER BY due_at NULLS LAST.

Acceptance
- Logging in as hr_staff shows Task Library, My Tasks, Templates. Navigating to each route highlights only that item.
- Logging in as manager hides Task Library and Templates. Visiting /tasks returns 403 and shows a friendly error.
- Candidate Tasks appear on /candidates/[id] only. There is no page that lists all candidate tasks globally.
- My Tasks lists only tasks assigned to the current user and each row links to /candidates/[id]#tasks.
