 Feature: New Candidate dialog

Goal
- Add a “New Candidate” dialog on /candidates that creates a candidate and immediately applies a template via expand_template.
- After create, navigate to /candidates/[id] and show the Tasks section.

Roles and access
- Allow: system_admin, hr_staff, department_admin, division_leader, manager.
- Deny: candidate.
- Department_admin may only create within their department. Division_leader only within their division. Manager only within their department.

Dialog trigger
- Button: “New Candidate” on /candidates (top right).

Form fields
- Salutation (required, select from salutation_type enum)
- First Name (required, text)
- Last Name (required, text)
- Email (required, email format, unique within department)
- Candidate Type (required, select from candidate_types)
- Department (required, select from departments where archived = false)
- Division (optional, select filtered by Department; list divisions where archived = false and division.department_id = Department)
- Manager (optional, select from users where role in {manager, hr_staff, system_admin} filtered by Department or Division)
- Start Date (required, date)
- Template (required, select from templates where is_active = true and (template.candidate_type_id = Candidate Type))
- Notes (optional, textarea)

UX behavior
- Disable “Create” until all required fields are valid.
- When Candidate Type changes, re-filter Template options.
- When Department changes, re-filter Division and Manager options.
- Show a “Preview due dates” panel: given Start Date and selected Template, call a local helper to compute display due dates using the same logic as the server (no write).
- Submit options: single “Create Candidate” button that creates the candidate and then applies the template.

API contracts
- POST /api/candidates
  body: {
    first_name, last_name, email,
    candidate_type_id, department_id, division_id?, manager_id?,
    start_date, notes?
  }
  returns: { id }

- POST /api/candidates/:id/apply-template
  body: { template_id }
  behavior: calls expand_template(template_id, :id), returns created task count.

Server logic
- Validate role and scope before insert.
- Enforce unique constraint on lower(email), department_id.
- Insert candidate with:
  - status = 'active'
  - created_by = current_user
- Then call expand_template(template_id, new_candidate_id).
  - Guards: template.is_active = true, candidate.start_date not null, candidate.template_locked = false, candidate has zero candidate_tasks.
  - On success: set candidate.template_applied_from_id, template_applied_at = now(), template_locked = true.
- On error, delete the candidate row and return 400 with a clear message.

Client success flow
- After both requests succeed, route to /candidates/[id] and scroll to “Tasks” section.
- Toast: “Candidate created and tasks generated.”

Validation rules
- First/Last Name required.
- Email required and valid format. If duplicate for the same department, show “Email already exists in this department.”
- Candidate Type required.
- Department required.
- Start Date required and must be today or a future date.
- Template required and must match Candidate Type.
- Division must belong to the selected Department when provided.

Edge cases
- If the template application fails, show an error and keep the dialog open. Do not leave a half-created candidate.
- If the user changes the Start Date after preview, recompute the preview only. The actual due dates come from the server when expand_template runs.

UI details
- Use shadcn/ui Dialog, Selects, Date picker, and Button.
- Use a two-column layout on desktop; single column on mobile.
- Show read-only badges for Candidate Type and Template in the confirmation step.
- Do not show any global tasks page. Candidate tasks are only visible on the Candidate profile.

TanStack Query keys
- ['candidates']
- ['candidates', id]
- ['templates', { candidateTypeId }]
- ['departments']
- ['divisions', { departmentId }]
- ['users', { roleFilter, departmentId?, divisionId? }]

Acceptance
- HR Staff can create a candidate, pick a template, and on submit lands on Candidate profile with tasks present.
- Required field validation blocks submit until valid.
- Template list filters by Candidate Type.
- Division and Manager lists filter by Department.
- On success, candidate.template_locked = true and template_applied_from_id is set.
- Users without permission cannot see the “New Candidate” button.
