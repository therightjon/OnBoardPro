Feature: Editable Candidate Status with Controlled Transitions

Goal
- Make candidate status editable on the Candidate Details page.
- Use ENUM candidate_status: ['draft', 'active', 'on_hold', 'completed', 'canceled', 'archived'].
- Enforce allowed transitions to keep the candidate lifecycle clean.
- Reflect status changes immediately in UI and candidate listing.
- Restrict updates to system_admin and hr_staff roles.

DB
- Already has candidate.status ENUM column; no schema change needed.
- Optionally: add archived_at, archived_by columns if not present.

API
PATCH /api/candidates/:id/status
Body:
{
  "status": "draft" | "active" | "on_hold" | "completed" | "canceled" | "archived",
  "closeOpenTasks"?: boolean    // only used when canceling
}
Behavior:
- Validate new status ∈ ENUM.
- Enforce allowed transitions:

  draft → active, on_hold, canceled, archived
  active → on_hold, completed, canceled, archived
  on_hold → active, canceled, archived
  completed → archived
  canceled → archived (or active with confirmation + optional task reset)
  archived → active (restore)

- Disallow:
  • completed → active / on_hold
  • archived → on_hold / completed / canceled / draft
- If transition invalid, return 400 { code: "INVALID_STATUS_TRANSITION" }.

- Side effects:
  • completed: check all required tasks complete. If not, reject with { code: "INCOMPLETE_TASKS", remainingTasks: [...] }.
  • canceled: if closeOpenTasks=true, set open candidate_tasks.status = "canceled".
  • archived: set archived_at=now(), archived_by=current_user.
  • archived → active: clear archived_at/by.

- Update candidate.updated_at and updated_by always.

Frontend
Candidate Details Page
- Status badge becomes a DropdownMenu (shadcn/ui).
- Menu options are ENUM values. Current status is highlighted.
- Options filtered by allowed transitions (based on current status).
- Selecting a new status:
  • For destructive transitions (→ canceled, archived, completed with open tasks), show a confirmation modal.
  • Completed: if server rejects with INCOMPLETE_TASKS, show modal listing remaining tasks.
  • Canceled: modal includes a checkbox “Close all open tasks”.
  • Archived: modal explains candidate will be hidden from active lists.
  • Archived → active: modal explains candidate will be restored.

- On confirm: call PATCH /api/candidates/:id/status.
- Optimistically update UI badge and invalidate queries:
  - ['candidate', id]
  - ['candidates']

- Badge styles:
  draft: gray
  active: green
  on_hold: yellow
  completed: blue
  canceled: red
  archived: dark gray

RBAC
- Only system_admin and hr_staff see dropdown. Others see static badge.

Acceptance
- User clicks status badge and sees only valid next statuses.
- Transition to completed blocked if required tasks incomplete; modal lists missing tasks.
- Transition to canceled shows modal; user can close tasks in bulk.
- Transition to archived hides candidate from default listing.
- Archived candidates can be restored to active only.
- Candidate list and detail update immediately without refresh.
- Unauthorized users cannot edit status.
