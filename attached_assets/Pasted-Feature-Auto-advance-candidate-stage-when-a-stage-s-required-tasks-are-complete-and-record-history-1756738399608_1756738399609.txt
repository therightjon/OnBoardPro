Feature: Auto-advance candidate stage when a stage’s required tasks are complete, and record history

Goal
- When a task status changes, check if the candidate’s current stage is now complete.
- “Complete” = all required candidate_tasks in that stage have status = 'done' and not archived.
- If complete, move candidate to the next stage (by order) and insert a row in candidate_stage_history.
- Record who caused the change (changed_by = current user).
- Show the updated stage and history immediately on the Candidate Details page.

Database (idempotent):

Server logic

1) Add a helper that advances stage if needed.
   File: server/services/candidates/advanceStage.ts

   Pseudocode (TypeScript + Drizzle, translate to your stack):
   ----------------------------------------------------------------
   export async function advanceStageIfComplete(db, {
     candidateId,
     invokerUserId
   }: { candidateId: string; invokerUserId: string }) {
     // Load candidate with current stage and the ordered stage list
     const candidate = await db.query.candidates.findFirst({
       where: (t, { eq }) => eq(t.id, candidateId),
       with: { }
     });
     if (!candidate) return { advanced: false };

     // Determine current stage:
     // 1) Prefer candidates.current_stage_id if set
     // 2) Else infer from the latest candidate_stage_history.to_stage_id
     // 3) Else default to the first stage by order_index
     const stages = await db.query.hiringStages.findMany({
       orderBy: (t, { asc }) => [asc(t.order_index)]
     });
     if (!stages.length) return { advanced: false };

     let currentStageId = candidate.current_stage_id;
     if (!currentStageId) {
       const last = await db.query.candidateStageHistory.findFirst({
         where: (t, { eq }) => eq(t.candidate_id, candidateId),
         orderBy: (t, { desc }) => [desc(t.changed_at)]
       });
       currentStageId = last?.to_stage_id ?? stages[0].id;
       // persist for faster next time
       if (!candidate.current_stage_id) {
         await db.update(candidates)
           .set({ current_stage_id: currentStageId })
           .where(eq(candidates.id, candidateId));
       }
     }

     // Is current stage complete? Required tasks only.
     const openRequired = await db.$queryRaw/* sql */`
       SELECT 1
       FROM candidate_tasks
       WHERE candidate_id = ${candidateId}
         AND stage_id = ${currentStageId}
         AND required = true
         AND archived = false
         AND status <> 'done'
       LIMIT 1
     `;
     if (openRequired.length > 0) return { advanced: false };

     // Find next stage
     const currentIdx = stages.findIndex(s => s.id === currentStageId);
     if (currentIdx === -1 || currentIdx === stages.length - 1) return { advanced: false }; // already at last stage

     const nextStageId = stages[currentIdx + 1].id;

     // Advance inside a transaction
     await db.transaction(async (trx) => {
       await trx.update(candidates)
         .set({ current_stage_id: nextStageId, updated_at: new Date() })
         .where(eq(candidates.id, candidateId));

       await trx.insert(candidateStageHistory).values({
         id: crypto.randomUUID(),
         candidate_id: candidateId,
         from_stage_id: currentStageId,
         to_stage_id: nextStageId,
         changed_at: new Date(),
         changed_by: invokerUserId,
         created_at: new Date(),
         updated_at: new Date()
       });
     });

     return { advanced: true, toStageId: nextStageId };
   }
   ----------------------------------------------------------------

Business rules

- Required tasks only gate progression. Non-required tasks do not block.
- Advancement is one stage at a time based on hiring_stages.order_index.
- No automatic regression when tasks in a previous stage are modified later.
- When a candidate is already in the last stage, do nothing.
- RBAC: only users who can edit tasks can trigger advancement through a status change.

Acceptance

- When the last required task in the current stage is set to Done, the candidate moves to the next stage, current stage label updates, and an entry is appended to candidate_stage_history with from_stage_id, to_stage_id, changed_by.
- Timeline tab shows the new entry in chronological order.
- Reopening a task in a completed stage does not move the candidate backward.
- No duplicate history rows are created for repeated checks when already at the next stage.
