Feature: Template-specific stage flows (with a global stage catalog)

Goal
- Allow different Templates (often by candidate type) to use different stage sequences.
- Keep one global catalog of stages (hiring_stages), but map/order the stages per template.
- Ensure template_tasks may only reference stages that belong to that template.

Schema (Postgres 16, idempotent)

-- global catalog already exists:
-- hiring_stages(id uuid pk, name text, order_index int, archived boolean default false)

-- 1) Map stages to a template with explicit order
DO $$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM information_schema.tables WHERE table_name='template_stages') THEN
    CREATE TABLE template_stages (
      id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
      template_id uuid NOT NULL REFERENCES templates(id) ON DELETE CASCADE,
      stage_id uuid NOT NULL REFERENCES hiring_stages(id),
      order_index integer NOT NULL DEFAULT 0,
      is_active boolean NOT NULL DEFAULT true,
      created_at timestamp NOT NULL DEFAULT now(),
      updated_at timestamp NOT NULL DEFAULT now()
    );
  END IF;
END$$;

CREATE UNIQUE INDEX IF NOT EXISTS uniq_template_stage
  ON template_stages(template_id, stage_id)
  WHERE is_active = true;

CREATE INDEX IF NOT EXISTS idx_template_stages_order
  ON template_stages(template_id, order_index);

CREATE OR REPLACE FUNCTION set_updated_at() RETURNS trigger AS $$
BEGIN NEW.updated_at = now(); RETURN NEW; END; $$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_template_stages_updated_at ON template_stages;
CREATE TRIGGER trg_template_stages_updated_at
  BEFORE UPDATE ON template_stages
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

-- 2) Guard: template_tasks.stage_id must belong to the template
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint WHERE conname = 'fk_template_tasks_stage_in_template'
  ) THEN
    ALTER TABLE template_tasks
    ADD CONSTRAINT fk_template_tasks_stage_in_template
    FOREIGN KEY (template_id, stage_id)
    REFERENCES template_stages(template_id, stage_id)
    DEFERRABLE INITIALLY DEFERRED;
  END IF;
END$$;

-- 3) Optional: candidates.current_stage_id must be a stage used by the applied template
-- (Skip if you don't store current_stage_id, or enforce in application code.)

API/Service changes

- When creating or editing a Template:
  - Provide a "Stages" editor that lets users pick stages from the global catalog and order them.
  - Write rows to template_stages with order_index 1..N.
  - Only allow adding Template Tasks for stage_ids present in template_stages for that template.

- expand_template(template_id, candidate_id):
  - Use the per-template order from template_stages (NOT global hiring_stages.order_index).
  - If candidate.current_stage_id is null, set it to the first active template_stages.order_index.

- advanceStageIfComplete():
  - Load the ordered list from template_stages for the candidate’s template_applied_from_id.
  - Advance to the next stage in that per-template sequence.
  - Insert candidate_stage_history(from_stage_id, to_stage_id, changed_by).
  - Do nothing if already at the last active template stage.

Frontend

- /templates/[id]
  - Add a "Stages" section (sortable list):
    • Left panel: global stage catalog (hiring_stages where archived=false).
    • Right panel: this template’s stages with drag-and-drop ordering.
    • Persist to /api/templates/:id/stages (POST/PATCH/DELETE) operating on template_stages.
  - In “Add Template Task” modal, Stage select should read from template_stages for this template (ordered by order_index).

- Candidate Details
  - Current stage label should resolve through template_stages (so order matches the template).
  - Timeline tab unchanged; it displays history rows with stage names from hiring_stages.

Routes to add

- GET  /api/templates/:id/stages        → list template_stages joined to hiring_stages (id, name, order_index, is_active)
- POST /api/templates/:id/stages        → add stage_id(s) with order_index
- PATCH /api/template-stages/:id        → reorder or toggle is_active
- DELETE /api/template-stages/:id       → archive/soft-delete

Validations

- Prevent adding the same stage twice to a template (unique index covers it).
- Prevent adding template_tasks with stage_id not present in template_stages for that template (FK covers it).
- When removing a stage from a template that already has template_tasks:
  - Block with a clear error, or
  - Soft-disable is_active and require the user to move or delete affected template_tasks first.

Acceptance

- Different templates can have different stage sequences and counts.
- “Add Template Task” only lists the template’s stages.
- expand_template seeds candidate.current_stage_id to the first template stage.
- Auto-advance uses the template’s stage order.
- Stage history writes the correct from/to stages on advancement.
